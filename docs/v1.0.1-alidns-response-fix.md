## 二、修复一：统一响应解析逻辑

### 2.1 根因分析

阿里云 API 的惯用做法是错误以 HTTP 200 返回，错误信息编码在 JSON body 中：

```json
{
  "Code": "InvalidAccessKeyId.NotFound",
  "Message": "Specified access key is not found.",
  "RequestId": "..."
}
```

而旧代码在 7 个方法中重复以下模式：

```rust
// 只在 HTTP 非 200 时解析错误 → 漏掉了 HTTP 200 的错误响应
if !status.is_success() {
    let err_body: AliDnsErrorResponse = response.json().await...;
    return Err(...);
}
// HTTP 200 时直接按成功类型解析 → 错误 JSON 反序列化失败
let success: AliDnsDomainListResponse = response.json().await...;
```

### 2.2 解决方案

新增 `parse_response<T>()` 辅助方法，统一所有方法的响应解析：

```rust
async fn parse_response<T: DeserializeOwned>(
    &self,
    response: reqwest::Response,
    context: &str,
) -> Result<T, ProviderError> {
    let body_text = response.text().await...;

    // 1. 优先匹配错误格式（无论 HTTP 状态码）
    if let Ok(err_body) = serde_json::from_str::<AliDnsErrorResponse>(&body_text) {
        if err_body.code.is_some() || err_body.message.is_some() {
            return Err(ProviderError::AliDns { code, message });
        }
    }

    // 2. HTTP 错误兜底
    if !status.is_success() { ... }

    // 3. 解析成功类型，失败时携带 body 前 500 字符
    serde_json::from_str::<T>(&body_text).map_err(|e| {
        ProviderError::Deserialization(format!("AliDNS {} parse error: {}. Body: {}", ...))
    })
}
```

## 三、修复二：DnsServers 数据模型修正

### 3.1 根因分析

阿里云 `DescribeDomains` API 实际返回的 `DnsServers` 结构为：

```json
"DnsServers": {
  "DnsServer": ["dns7.hichina.com", "dns8.hichina.com"]
}
```

旧模型将此字段定义为 `Option<Vec<String>>`，期望的是扁平数组 `["dns7.hichina.com", ...]`。当 serde 遇到 JSON 对象 `{...}` 反序列化到 `Vec<String>` 时，报错 `invalid type: map, expected a sequence`。

### 3.2 解决方案

新增包装结构体，映射阿里云 API 的实际 JSON 结构：

```rust
#[derive(Debug, Deserialize)]
struct AliDnsServers {
    #[serde(rename = "DnsServer")]
    dns_server: Vec<String>,
}
```

`AliDnsDomain.dns_servers` 字段类型从 `Option<Vec<String>>` 改为 `Option<AliDnsServers>`。

两处映射代码同步更新：

```rust
// 旧
name_servers: d.dns_servers.unwrap_or_default(),

// 新
name_servers: d.dns_servers.map(|s| s.dns_server).unwrap_or_default(),
```
